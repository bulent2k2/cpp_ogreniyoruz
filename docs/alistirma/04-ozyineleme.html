ZorlayıcıIV-4-Z1 Güzel permütasyon

CSES 1070: 1..n'in öyle bir dizilişi ki komşu sayıların farkı hiç 1 olmasın. Önce n = 5 için bütün dizilişleri üretip ilk uygun olanı yazın. Sonra kitapçığın asıl sorusu: üretmeden, doğrudan kurun — önce çiftler sonra tekler neden işe yarar? Hangi n'lerde hiç çözüm yok? Girdi 7; çıktı iki satır: üretimle bulunan (sözlük sırasında ilk uygun olan; n ≤ 8 için) ve doğrudan kurulan. İkisi farklı; ikisi de doğru.

Düşünce

İki yol: bütün dizilişleri deneyip ilk uygun olanı bulmak, ya da çiftleri sonra tekleri yazmak.

Yaklaşım

Üretim: vector<int> p 1..n, do { if (guzelMi(p)) break; } while (next_permutation(...)). Doğrudan: n = 1 için 1, n = 2 ve 3 için çözüm yok, n ≥ 4 için 2 4 6 … sonra 1 3 5 ….

İlk satır

bool guzelMi(const vector<int>& p) { for (size_t k{1}; k < p.size(); ++k) if (abs(p[k] - p[k-1]) == 1) return false; return true; }

Kitapçığın dördüncü alıştırmasındaki “zor”: başka bir budama kuralı bulun. Bir aday: hedefe erken varırsak (kalan > 0 iken) o dal ölmüştür, hemen dönün. Bir başkası: hedef kare dört yandan kapanmışsa. Her kuralı eklemeden önce kâğıtta “bu dalda gerçekten çözüm olamaz” diye bir kanıt yazın (kitapçığın beşinci alıştırması). Girdi 5 5; patika sayısı yine 104 olmalı (değilse kural yanlış). Çağrı sayısı IV-6-A2'den az çıkarsa kuralınız yeni dallar kesiyor; eşit çıkarsa kitapçığın kuralı o dalları zaten kesiyormuş — bu da bir ölçüm. Üç sayıyı yan yana yazın: budamasız, kitapçığın, sizin.

Düşünce

Yeni bir budama: hedefe erken varmak ya da hedefin kapanması dalı öldürür.

Yaklaşım

git'in başında: if ((r, c) hedef and kalan > 0) return;; kural numarasına göre if (kural >= 1) kitapçığın denetimi, if (kural == 2) sizinki. Üç kuralı üç kere çalıştırıp çağrıları yazın.

İlk satır

if (r == S - 1 and c == 0 and kalan > 0) return; // hedefe erken vardık
